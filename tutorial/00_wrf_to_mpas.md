# 第 0 课：从 WRF 走到 MPAS，先把整条路看明白

如果你已经熟悉 WRF，学习 MPAS 不用从大气模式的基本原理重新开始。真正需要适应的，
是水平网格、资料预处理和空间下标。WRF 在投影后的矩形网格上计算，MPAS 则把多边形
铺满球面。本课先把两套模式的对应关系讲清楚，暂时不运行程序。

读完这一课，你应该能说清三件事：水平网格在哪里确定，GFS 资料怎么进入模式，静态
地理资料又在什么地方与气象资料汇合。

![WRF 到 MPAS 的资料准备过程](images/wrf_mpas_workflow.svg)

先看图中的 MPAS 部分。这里有两条各自独立的支路：

- `grid.nc` 与 WPS_GEOG（WPS 静态地理资料目录）一起生成 `static.nc`；
- GFS 资料经过 `ungrib.exe` 解码，生成 `FILE:*` 中间文件。

两路资料直到制作 `init.nc` 时才碰面。`grid.nc` 因此不是 `ungrib.exe` 的输入。这个
关系很重要，后面排查初值制作问题时，经常要沿着这两条支路分别检查。

## 先认识网格上的三个位置

MPAS 网格由多边形组成。一个多边形区域叫网格单元（**cell**），两个单元共用的线段叫
边（**edge**），几条边相交的点叫顶点（**vertex**）。文件里的 `nCells`、`nEdges`、
`nVertices`，分别表示这三类位置的总数，不是 WRF 里的南北、东西格点数。

这一课只需先记住名字。第 3 课会把真实网格画出来，仔细看它们怎样相连；第 7 课再讲
温度、风和涡度分别放在哪一类位置上。

## 用 WRF 的经验来理解 MPAS

| 你在 WRF 中做的事 | MPAS 中怎样做 | 需要特别留意的地方 |
|---|---|---|
| 用 `geogrid.exe` 定义区域 | 选择或生成 `grid.nc` | 运行模式前，水平网格已经写进文件 |
| 设置中心点、投影、`dx/e_we` | 选择网格，必要时移动已有加密区 | 不能靠 namelist 临时生成全球网格 |
| 用 `ungrib.exe` 解码 GFS | 仍然使用 `ungrib.exe` | 解码时还不需要知道最终采用哪张 MPAS 网格 |
| 运行 `metgrid.exe` 和 `real.exe` | 运行 MPAS 初始化程序 | 它负责插值到非结构网格，并建立垂直状态 |
| 得到 `wrfinput_d01` | 得到 `*.init.nc` | 文件里保存 MPAS 网格上的起报状态 |
| 得到 `wrfbdy_d01` | 全球算例不需要对应文件 | 闭合球面没有侧边界 |
| 修改 `namelist.input` | 修改 `namelist.atmosphere` 和 `streams.atmosphere` | 前者管计算，后者管文件读写 |
| 使用 `(south_north, west_east)` | 使用 `nCells/nEdges/nVertices` | 非结构网格没有规则的 `i,j` 下标 |

仓库安装后会得到 `mpas_init_atmosphere`。案例脚本还会给它建立一个软链接，名字是官方
文档常见的 `init_atmosphere_model`。这两个名字指向同一个初始化程序，是同一步的两个叫法。

## 从网格到初值，会遇到哪些文件

先把四类主要文件认清：

1. `grid.nc`：保存网格位置、面积和相邻关系，相当于一只已经划好格子的地球仪；
2. `static.nc`：在这张网格上加入地形、土壤、土地利用等静态资料；
3. `FILE:*`：WPS 从 GFS 中解码出的中间格式（intermediate format）气象资料；
4. `init.nc`：把 `static.nc` 和起报时刻的气象资料合在一起，形成模式初值。

只有 `init.nc` 还不能直接完成预报。运行时还需要 namelist、streams、物理过程查找表和
MPI 网格分区文件。它们会在第 3、5、6 课首次用到时逐个解释，不必现在死记名字。

本教程先做全球算例，所以不需要侧边界条件（LBC）。
以后如果裁剪有限区域，才需要准备侧边界资料。

## 这一步留下了什么

本课只是在脑中搭起流程，没有要求你执行命令，也不会在磁盘上生成新文件。此时仓库目录
应该保持原样。流程图和上面的文件名是后续课程的地图，现在不要按它手工创建文件。

```text
MPAS_tutorial/
├── AGENTS.md
├── README.md
├── install_mpas.sh
├── tutorial/
├── tools/
└── ...                       # 其余已有内容保持不变
```

下一课真正要设置的是安装命令的参数，例如编译器位置和安装前缀。`grid.nc`、`static.nc`
和 `init.nc` 会在后续课程中依次下载或生成，现在不需要提前准备。

## 用自己的话讲一遍

先合上正文，再回答下面三个问题：

1. 为什么 `namelist.atmosphere` 里没有 WRF 常用的 `dx` 和 `e_we`？
2. 更换 MPAS 网格以后，为什么 GFS 解码得到的 `FILE:*` 通常还能复用，而 `static.nc`
   必须重新制作？
3. 为什么全球 MPAS 算例没有 `wrfbdy_d01` 对应的文件？

如果一时讲不顺，就回头看本课开头的流程图，分别沿着网格、GFS 和侧边界三条线再走一遍。
